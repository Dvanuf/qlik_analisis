# Qlik Анализатор — описание проекта

**Главный обзорный документ.** Обновляется при каждой существенной доработке —
это правило записано в [AGENTS.md](../AGENTS.md) (раздел 0). Детали состояния
прогонов — в [STATE.md](STATE.md), история версий — в [CHANGELOG.md](../CHANGELOG.md),
планы и бэклог — в [PLAN.md](PLAN.md) и [ROADMAP.md](ROADMAP.md).

**Текущая версия:** 0.34.0 · тесты ядра: 561/561 · Node ≥ 22, ESM · Electron 45

## 1. Что это

Десктоп-приложение (Electron) для **аудита качества приложений Qlik Sense и
QlikView**: подключается к хабу/движку или файлу скрипта, разбирает скрипт
загрузки, модель данных, объекты и выражения, прогоняет каталог правил,
считает оценку 0–100 по доменам и показывает результат в интерфейсе с
конкретными правками. Для QlikView-приложений поддержан вход через хаб и
QlikView AccessPoint (NTLM). Работает полностью офлайн: ИИ-слой opt-in,
ключи хранятся локально в зашифрованном виде.

**Для кого:** команда разработки Qlik, которая хочет системно находить
лишние данные, синтетические ключи, ошибки мер и скриптов — и видеть, что
именно доработать в исходниках.

**Репозиторий:** `https://github.com/Dvanuf/qlik_analisis` (main).
**Исходники:** `/Users/anufriev_d_v/.cline/data/workspaces/chat/qlik-analyzer`.

## 2. Возможности (вкладки интерфейса)

| Вкладка | Что делает |
|---|---|
| **Оценка** | Аналитическая карточка по макету: кольцо с баллом, вердикт, плитки находок, домены таблицей с диагнозами, топ-5 исправлений с «Открыть»/«Применить», прогноз |
| **Сводный отчёт** | Группа приложений: фильтры, 6 показателей, динамика, тепловая карта «приложение × домен», главные проблемы, PDF руководителя, Excel/CSV |
| **Анализ** | Метрики, карточки доменов, чек-лист всех правил по доменам, находки с переходом к строке скрипта, панель паттерна, подавление `// qa-ignore` |
| **Скрипт загрузки** | Текущий скрипт с номерами строк и подсветкой, находки привязаны к строкам, поиск (Ctrl+F) |
| **Улучшенный скрипт** | Предложенная версия (правки правил или предложение ИИ), **частичное форматирование** — панель «Что форматировать» по вкладкам `///$tab`, кнопка «Формат», экспорт .qvs показанной версии |
| **Модель данных** | Книга Excel: таблицы, поля, объекты, переменные, master-объекты, подключения |
| **Формирование** | **Модель данных в трёх состояниях** (подробно — раздел 6): «с учётом дропнутых — как сформировано», «текущая финальная», «рекомендованная — после правок»; каждая секция сворачивается; карточка «Качество модели» наверху; проблемы бейджами по типам; чипы-фильтры |
| **ИИ-чат** | Вопросы к модели по агрегированной сводке (не весь скрипт): Z.ai → Gemini → локальная модель; переписка в localStorage per-app |
| **Каталог функций** | 15 готовых SUB-подпрограмм с сигнатурами, копирование и выгрузка .qvs |
| **Подключение** | Пошаговый вход в хаб (Sense) и AccessPoint (QlikView, NTLM), выбор приложений галочками, настройки GitLab-включений, репозиторий QRS |
| **Правила** | Включение/выключение правил, важность, пороги, пресеты, настройки оценки; хранение в rules.json |

Горячие клавиши: Ctrl/Cmd+1…9, Ctrl+0 — вкладки; Ctrl+F — поиск по скрипту; Esc — закрыть панель.

## 3. Архитектура

```
desktop/electron/main.ts ── IPC ──► renderer (React/TS, desktop/src/tabs/*)
        │
        ▼
src/ (ядро, чистый Node ESM, детерминированное — без сети/времени/рандома)
  verify/     gitlab-sync.js (сверка скрипта с эталоном GitLab, L013)
  extract/    engine.js (QIX WS, GetDocList/объекты/связи), docapi.js (QlikView 12),
              file.js (qvs/qvw-контейнер), qrs.js (сертификаты), gitlab.js,
              includes.js (раскрытие $(Must_Include)), session.js (сессия хаба), ntlm.js
  script/     parse.js → outline.js, lineage.js, format.js (форматтер + секции ///$tab),
              refactor.js (единый механизм правок), library.js, usage.js
  rules/      64 правила (quality/resources/advanced/metadata/practices/script),
              index.js (runRules), domains.js (6 доменов), platforms.js, config.js
  findings/   dedupe.js (сворачивание), group.js, patterns.js, suppress.js, locations.js
  score/      index.js — оценка v2: вес паттерна w×(1+log2 n), потолки 40/30/10,
              wasted-штраф за лишние данные; ВСЕ 6 доменов всегда в summary.domains
  report/     html.js, csv.js, xlsx.js (свой генератор), data-model.js,
              data-schema.js (модель в трёх состояниях — см. раздел 6), heatmap.js
  ai/         index.js (агрегация, обезличивание, лимиты), openai.js, chat-store.js
  history.js  SQLite история прогонов, сравнение с базовой линией
```

Поток анализа: **экстракция → граф → индекс (graph.js) → правила → находки →
паттерны → оценка → отчёты**. Результат `analyze()` содержит: `findings`,
`ruleStats`, `patterns`, `summary` (score/domains/top/…), `outline`, `lineage`,
`schema`, `dataModel`, `expressionIndex`, `patch`.

## 4. Каталог правил и оценка

- **64 правила**, ID: Q (качество выражений), R (ресурсы/модель), P (практики),
  S (скрипт). Применимость по платформам — `RULE_PLATFORMS` (`src/rules/platforms.js`).
- **6 доменов** (`src/rules/domains.js`): Модель данных, Скрипт загрузки,
  Дашборд и объекты, Меры и выражения, Переменные, Подключения и окружение.
- **Ключевые правила модели**: R001/R002 (неиспользуемые поля), R003 (неиспользуемые
  таблицы), R005/R006 (пустое), R007 (AutoNumber), R009 (константы), R010 (неполный
  ключ, subsetRatio), R011 (1:1 — можно объединить), R020 (высокая кардинальность),
  R021 (CONCATENATE без ключа), R022 (M:N), R023 (мера/поле с одним именем),
  P005/P012 (синтетические ключи).
- **Оценка v2** (`scoreVersion: 2`): штраф паттерна `w×(1+log2 мест)`, потолки
  по важности, отдельный wasted-штраф (R001/R003/R005 → доля строк). Тренд
  считается только внутри версии. Домены без находок имеют score 100 — они
  всегда присутствуют в `summary.domains` (0.29.2).
- Настройки: `rules.json` (userData) — enabled/disabled, важности, пороги,
  исключения, suppress, scoring, **formatting** (indent, commaStyle, alignAs…).

## 5. Форматтер и частичное форматирование

- `src/script/format.js` — форматтер QVS: отступы по стеку блоков
  (SUB/FOR/DO/IF…THEN/SWITCH), LOAD/SELECT — одно поле на строку с запятыми
  (leading/trailing), маскирование защищённых фрагментов (строки, `//`,
  `/* */`, REM, `$(…)`, `{<…>}`) с **предохранителем** (незакрытый фрагмент
  длиннее 200 строк не глотает файл); `//` внутри `[скобок]` — не комментарий
  (`lib://…`); запятые внутри функций (ApplyMap/If/Sum…) не режут поле —
  разрезание только по запятым верхнего уровня; зоны `// fmt:off` защищают
  и отступы, и перестроение LOAD.
- `splitScriptSections` / `formatScriptSections` — деление по `///$tab` и
  выборочное форматирование (предупреждения с префиксом `[имя вкладки]`).
- Кнопка «Формат» на «Улучшенном скрипте»: панель «Что форматировать»
  (чекбоксы секций), экспорт/копирование берут показанную смесь.

## 6. Вкладка «Формирование» — модель данных в трёх состояниях

По утверждённому макету `mockups/model-tab-mockup.html` (0.29.0), упрощено
в 0.29.1: lineage-граф и «Документ» убраны — вкладка показывает только модель.

- **Карточка «Качество модели» наверху**: кольцо с баллом домена «Модель
  данных», вердикт, счётчики (ошибки/предупреждения/замечания/синт.ключа),
  чипы худших таблиц; строка «прогон: платформа X · объектов N».
- **Чипы-фильтры** со счётчиками: Все / Только проблемное / Синт.ключи /
  Неисп.поля / M:N / Неполные ключи — непрошедшие таблицы гаснут.
- **Три секции-аккордеона** (`src/report/data-schema.js → buildDataSchema`):
  1. **asBuilt** — «с учётом дропнутых — как сформировано»: движковые таблицы
     + промежуточные и DROP из lineage (зачёркнуты), RESIDENT/JOIN/CONCATENATE-рёбра;
  2. **final** — «без дропнутых — текущая (финальная) модель» (раскрыта по умолчанию);
  3. **afterFix** — «рекомендованная — после правок»: минус fix dropField/dropTable
     (помечено «−»).
- **Проблемы по типам** (`problemsByType`): unusedFields (R001/R002),
  unusedTable (R003), synthetic (P005/P012), incompleteKeys (R010 + subsetRatio),
  mn (R022), merge 1:1 (R011), empty (R005/R006/R009), cardinality (R020),
  errors, **overload 0–100** (доля лишних строк/полей — полоска на таблице).
- Клик по таблице/полю — находки по типам и «Показать в Анализе».
- **Честная карточка**: если проверки модели пропущены, карточка разделяет
  причины — «Выключены во вкладке „Правила": …» (skipped без note) и
  «Недостаточно данных» с точным советом по цифрам (`frontEndStats`:
  объектов / из них с выражениями / полей со ссылками — различает устаревшую
  сессию от ограничения API). «Чистые таблицы» при пропусках не означает «отлично».

## 7. Подключения, включения, секреты

- **Сессия хаба**: cookie+XRF/CSRF, per-host файлы
  `hub-credentials-<host>.bin` (safeStorage/Keychain). QlikView: AccessPoint
  login.htm, NTLMv2 (`src/extract/ntlm.js`), QRS по сессии (прокси /qrs) и
  по сертификату 4242.
- **Включения `$(Must_Include=…)`**: раскрываются автоматически — из папки
  репозитория (авто git pull), из **GitLab** (индекс .qvs по папкам, raw-чтение,
  токен в safeStorage) или по пути подключения из QRS. Нераскрытые — баннер.
- Секреты никогда не печатаются и не коммитятся; маскирование в логах —
  `src/logging/mask.js`.

## 8. Сборка, тесты, релиз

```bash
# окружение: Node v24 в .tools/node/bin или Electron-as-Node (см. AGENTS §10)
npm test                                  # ядро, node:test
cd desktop && npm run typecheck           # tsc --noEmit
cd desktop && npm run build               # main + preload + renderer (vite)
cd desktop && npm run smoke               # QA_SMOKE=1: автопроверка окна + скриншоты out/
cd desktop && npx electron-builder …      # или scripts/build-release.mjs — пересобирает всё сам
```

- **build-release.mjs сам пересобирает main и renderer** перед упаковкой
  (урок 0.27.3: релиз уходил с устаревшим бандлом).
- **smoke** проверяет: вкладки, «Формирование» (карточка качества + 3 секции
  схемы + скриншоты), ИИ-блоки (шаг «Промпт ИИ» пропускается в режиме
  конфиденциальности), chat localStorage, шрифты; JSON-отчёт в консоль,
  PNG в `out/` (или userData при упаковке).
- **Релиз по AGENTS §9**: версия `desktop/package.json` → build → smoke →
  CHANGELOG + STATE + release/README + ROADMAP → коммит → тег `v<версия>` →
  `git push origin main --tags` → **GitHub Release с 3 артефактами**
  (.exe x64 NSIS, .dmg, .zip arm64). Публикация обязательна.

## 9. Особенности сервера и окружения (критично)

- Хаб: `dc3-qliks-ap-03.onyx.local`, REST `/api/hub/v1/` (JSON:API),
  список — WebSocket `GetDocList`; WS требует `qlik-csrf-token`;
  своя сессия на каждое приложение; объекты `{qInfo:{qId,qType}}`.
- QlikView-импортированные приложения могут не отдавать ссылки на поля —
  R001/R002/R003 тогда пропускаются честно («Оценка неполная» в карточке).
- Node.js v24 в `.tools/node/bin`; Electron-as-Node — вариант 2;
  `ELECTRON_RUN_AS_NODE` нюансы, заглушки electron-builder, `arch` строкой —
  полный список ловушек в AGENTS §10 и STATE §5.
- Сессии протухают (403) — «Войти в хаб» перезаписывает per-host файл.

   в том же коммите, что и код.
2. Номера версий и текущие цифры тестов обновлять в шапке.
3. Подробности состояния/ловушек — в STATE.md; этот документ — «как устроено»,
   а не «что делали вчера».
4. Новое правило → раздел 4 (кратко, одной строкой в список ключевых).
