## Сделано в 0.20.0 – 0.22.0 (бэклог закрыт 09.11.2026)

**0.22.0 — весь «Новый бэклог»:**
1. **«Оценка» — аналитическая карточка**: заголовок-вывод, 4 плитки находок,
   полоса-композиция с инсайтом, домены таблицей с диагнозами («балл срезан
   N неприменимыми проверками»), агрегированный план топ-5, футер-предупреждение
   перед «Применить», блок «Что вне топ-5, но важно».
2. **«Подключение»: выбор только галочками** — автоподстановка первого
   приложения, радиокнопки и одиночная кнопка убраны; клик по строке = галочка.
3. **«Улучшенный скрипт»: форматирование** — `src/script/format.js`
   (отступы SUB/FOR/DO/IF/SWITCH по стеку блоков, чистка пробелов вне строк),
   тумблер «Формат», экспорт отдаёт показанную версию.
4. **Синхронная прокрутка** «было/стало», тумблер «Синхронно».
5. **Системные переменные** — `SYSTEM_VARIABLES` + тест: R004/S008 молчат.

**Ранее (0.20.0):** правила R022/R023/R024, R007/R001 исключения; сайдбар-меню
по образцу; версия в шапке; каталог правил в Excel; CI GitLab.

## Отложено (требует внешних ресурсов или живого сервера)

| Пункт | Причина отложения |
|---|---|
| X001 замер времени расчёта объекта | Нужны живые сессии Engine и проверка нагрузки на сервер; порог 3 с не откалиброван |
| L013 расхождение с GitLab | **Частично закрыто в 0.26.0**: чтение включений из GitLab сделано. Осталось: хеш нормализованного скрипта (приложение vs репозиторий) |
| Снимки свойств (схема QSDA Collection) | Крупный объём; имеет смысл после L013 и CI |
| Оценка экономии памяти у R001 | Источник размеров поля (байты) не проверен на живой версии Engine — без него оценка была бы фикцией |
| Полная виртуализация списков | Заменено лимитом высоты; виртуализация — только при подтверждённых тормозах |
| Полная доступность (aria/клавиатура/focus-trap) | Частично сделано (tablist-роли); остальное — при следующем UX-проходе |
| Унификация стилей + чистка мёртвого CSS | Косметика; делать вместе со следующим визуальным изменением |

- **Форматирование: условия видны в приложении** — в «Улучшенном скрипте»
  рядом с тумблером «Формат» — панель «Как форматируется» с человеческим
  перечнем текущих правил (блоки/отступы/чистка пробелов, что сознательно
  не делается) — из описания `src/script/format.js`, чтобы правила не
  расходились с кодом.
- **Форматирование: настраиваемое** — корректировка правил пользователем:
  размер отступа, чистка пробелов, выравнивание `AS [алиас]`, дополнительные
  конструкции блоков; хранение в rules.json (раздел formatting), применение
  в `formatScript(src, opts)`.
- **«Формирование»: схема модели данных с пометками проблем** — таблицы-боксы
  с перечнем полей и связями по ключам («снежинка»/звезда, как модель данных
  показывается в клиенте Qlik) — в дополнение к текущему lineage-графу
  «источники → таблицы → приложение». Прямо на схеме цветом выделяются
  ошибки полей и другие поводы для доработки таблиц-источников (видно без
  открытия таблицы находок). Со схемы запускается анализ качества модели
  данных.
- **Меры: отображение и правила качества** —
  1. Диагностика: выяснить, почему во многих приложениях меры
     не отображаются (в «Модели данных» и в метаданных анализатора).
     Цель отображения — проверка качества мер.
  2. Меры должны быть видны все: и мастер-меры, и меры, которые
     отображены в визуализациях (графиках) — вместе с их формулами.
  3. Когда подтверждено, что все меры (в графиках и мастер-меры)
     отображаются вместе с формулами — добавить правила проверки
     качества мер.
