# Состояние проекта qlik-analyzer — передача контекста

Документ отвечает на вопрос «с чего начать новую задачу». Правила работы с AI —
в [`AGENTS.md`](../AGENTS.md), история версий — в [`CHANGELOG.md`](../CHANGELOG.md).

**Обновлено:** 12.11.2026 · **Текущая версия:** 0.28.0 (тег `v0.28.0`)

Что можно перенести из расширения QS Metadata Explorer — в
[`QSME-ANALYSIS.md`](QSME-ANALYSIS.md) (проверено на живом хабе 26.10.2026).
Три блока из него перенесены в 0.5.5: метаданные фронт-энда, outline скрипта и каталог функций.
В 0.6.0 сделано ещё три: «Data model (Excel)», поиск по произвольному выражению и отдельный перечень историй (stories).

План улучшений и бэклог задач — в [`ROADMAP.md`](ROADMAP.md): разделы
«Правила этап 2», «UX», «Инфраструктура» и пустой бэклог, куда задачи
дописываются вручную; по команде «запускай план» берём оттуда.

Работа с сервером **QlikView** (Doc API 12) — в
[`QLIKVIEW.md`](QLIKVIEW.md): что отдаёт Doc API, какие из 54 правил
применимы к QlikView (26) и какие помечаются «Не применимо для платформы
QlikView» (28), авторизация через хаб, офлайн-режим и выгрузка скрипта из `.qvw`.

| Обязательное условие для WS | В URL должен быть **`qlik-csrf-token`**; без него сервер отвечает `403` |
| Корневые адреса хаба | `wss://host/` и `wss://host/app` → **`301`** (переадресуются) |
| Рабочие адреса для WS | `wss://host/app/<appId>` и служебный `wss://host/app/engineData` |
| Закрытие документа | В схеме QIX **нет метода `CloseDoc`** → документ нельзя закрыть в рамках сессии |
| Обход приложений подряд | Только **своя сессия на каждое приложение**, иначе «App already open» |
| Объекты приложений | **Отдаются** (проверено 26.10.2026): листы, истории, таблицы, listbox, treemap и объекты Sense 12 (`UniKPI`, `filterpane`, `piechart`, `action-button`) |
| Формат элемента объекта | Doc API отдаёт `{qInfo: {qId, qType}, qMeta, qData}` — идентификатор лежит **внутри** `qInfo` |
| Объекты вне перечня типов | Не возвращаются запросом по типам, но перечислены в `qChildList` листа — собираются обходом листов |
| Связи между таблицами | `GetAssociationScores(qTable1, qTable2)` — **два имени таблиц**; массивы и числа сервер отвергает («Invalid method parameter(s)») |
| Сведения об использовании полей | Через Doc API отдаются **не всегда**: у QlikView-приложений объекты приходят без ссылок на поля, поэтому правила «неиспользуемое поле» там недоказуемы и пропускаются |

**Вывод:** фронт-энд доступен, но с оговорками — часть приложений (импортированные
из QlikView) отдаёт объекты без сведений об используемых полях. Такие случаи
помечаются как «пропущено: недоказуемо», а не превращаются в находки.

## 4. Как проверить на реальном сервере

**Готовый инструмент:** [`tools/live-check.mjs`](../tools/live-check.mjs) — читает
сессию хаба (из `safeStorage`), подключается к движку и прогоняет настоящий
анализ с отчётом по метаданным, структуре скрипта и новым правилам. Секреты
не печатаются.

```bash
cd <проект>/desktop
./node_modules/electron/dist/Electron.app/Contents/MacOS/Electron \
  ../tools/live-check.mjs [appId ...]
```

Без `appId` берётся первое приложение из списка сервера. Если сессия истекла —
инструмент прямо скажет об этом (код 403) и предложит войти в хаб заново.

Если нужен отдельный скрипт, а не готовая проверка, учётные данные лежат
в `safeStorage` (Keychain). Расшифровать их можно тем же Electron, которым
собирается приложение:

```js
// /tmp/qa-read-creds.mjs
import { app, safeStorage } from 'electron';
import { readFileSync } from 'node:fs';
app.setName('qlik-analyzer-desktop');   // имя важно: ключ в Keychain привязан к нему
app.whenReady().then(async () => {
  const buf = readFileSync('/Users/anufriev_d_v/Library/Application Support/qlik-analyzer-desktop/hub-credentials.bin');
  const { result } = await safeStorage.decryptStringAsync(buf);
  console.log(result);
  app.quit();
});
```

```bash
cd <проект>
env -u ELECTRON_RUN_AS_NODE ./desktop/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron /tmp/qa-read-creds.mjs
```

**Внимание:** полученные cookie и ключи — это действующая сессия. Не коммитить,
не класть в отчёты, после проверки временные файлы удалять.

## 5. Особенности окружения (обязательно к знанию)

**Node.js v24 лежит в `<рабочая папка>/.tools/node/bin`** (не в системном PATH —
команда `node` может не сработать, тогда используй полный путь). Сборку
и electron-builder удобнее делать через Electron, который лежит в проекте:

```bash
PROJ=/Users/anufriev_d_v/.cline/data/workspaces/chat/qlik-analyzer
TOOLS=/Users/anufriev_d_v/.cline/data/workspaces/chat/.tools/node/bin
ELECTRON="$PROJ/desktop/node_modules/electron/dist/Electron.app/Contents/MacOS/Electron"

# тесты
cd "$PROJ" && ELECTRON_RUN_AS_NODE=1 "$ELECTRON" --test "test/*.test.js"
# типы
cd "$PROJ/desktop" && ELECTRON_RUN_AS_NODE=1 "$ELECTRON" ./node_modules/typescript/bin/tsc --noEmit
# сборка main и preload
cd "$PROJ/desktop" && ELECTRON_RUN_AS_NODE=1 "$ELECTRON" scripts/build-main.mjs
# сборка renderer
cd "$PROJ/desktop" && ELECTRON_RUN_AS_NODE=1 "$ELECTRON" node_modules/vite/bin/vite.js build
# релиз (артефакты в desktop/release/)
cd "$PROJ/desktop" && ELECTRON_RUN_AS_NODE=1 "$ELECTRON" scripts/build-release.mjs
```

Ловушки:

- В терминале VSCode выставлено `ELECTRON_RUN_AS_NODE=1`. Для запуска самого
  приложения нужно `env -u ELECTRON_RUN_AS_NODE`.
- Скрипты запускаются как `scripts/build-main.mjs` — **без** слова `node` перед
  путём (иначе Node ищет файл `node` и падает с MODULE_NOT_FOUND).
- `electron-builder` не запускается через CLI (yargs получает путь к скрипту как
  аргумент) — работает **программный API** `build({ targets, config })`.
- Под Electron-as-node нужно `process.noAsar = true`, иначе сборщик падает на
  `default_app.asar` («Invalid package»).
- `electronDownload.arch` задавать строкой (`'arm64'`/`'x64'`), иначе в
  `@electron/get` уходит число (`Arch.arm64 === 3`), кэш Electron не находится.
- Макрос `${arch}` в `artifactName` раскрывается числом — имена задаются явно:
  `${productName}-${version}-arm64.${ext}`.
- `npm list` для сбора зависимостей: production-зависимостей нет, достаточно
  заглушки `{"name":…,"version":…,"dependencies":{}}`.
- `safeStorage.decryptStringAsync` в Electron 45 возвращает объект, а не строку —
  для чтения файла сессии используйте `safeStorage.decryptString`.

## 7. Открытые вопросы и что не сделано

- **Объекты приложений собираются** — проверено на живом сервере 26.10.2026
  (01_EX_checker: 3 объекта и 2 листа; «Статистика Активности»: 33 объекта).
  Раньше их было 0 из-за неверного разбора ответа сервера.
- **Правило R011 работает**: связи запрашиваются по именам таблиц, связь 1:1
  засчитывается только при полном совпадении значений полей.
- **У QlikView-приложений** (импортированных, вроде `01_EX_App_QV`) объекты
  приходят без ссылок на поля, поэтому правила R001–R003 там пропускаются с
  объяснением. Это ограничение API, а не дефект инструмента.
- **Пакетный анализ 226 приложений** не проверялся целиком — только 3 подряд.
  Стоит прогнать на ограниченной выборке (`--limit 10`) и замерить время.
- **Кэш пакетного анализа** (`desktop/release/../.cache`) не проверен на
  инвалидирование при перезагрузке приложения.
- **Версия в заголовке** берётся из `app.getVersion()` — в dev-сборке показывает
  версию `package.json`, в упакованной — релизную.
- **Метаданные приложений проверены на живом хабе 27.10.2026**, остальное — нет:
  REST `/api/hub/v1/apps` отдаёт владельца (226/226), поток (90/226) и тэги
  (92/226) — механизм наполнения фильтров подтверждён на реальном сервере.
  Метаданные фронт-энда, outline, каталог функций, правки скрипта, ошибки
  скрипта и правила R019–R021 по-прежнему покрыты только модульными тестами
  (405/405) и smoke-проверкой упакованного приложения. Нужен прогон
  `tools/live-check.mjs` (раздел 4).
- **ИИ-слой проверен на поддельном сервере, не на живом ключе Z.ai**: протокол,
  агрегация, обезличивание, fallback и лимиты покрыты тестами (330/330), но
  реальный тариф Z.ai не проверен — нужно подтвердить, что `glm-4.5-flash`
  отвечает без пополнения баланса, и уточнить лимиты запросов в минуту.
- **R019 (неиспользуемое подключение) может давать ложные срабатывания**:
  `getConnections` на этом сервере возвращает 54 одинаковые серверные
  подключения для разных приложений — их не использует ни один объект.
  Проверить на живом хабе; при необходимости ограничить правило
  подключениями уровня приложения.
- **QRS-модуль проверен на живом сервере частично (07.11.2026):** порт 4242
  доступен, TLS поднимается (сервер — Microsoft-HTTPAPI, тело ответа пустое,
  причина — в reason phrase по HTTP/1.1). Без клиентского сертификата QRS
  отвечает `403 No client certificate supplied`, с одноразовым
  самоподписанным — `403 Client certificate invalid`. Подтверждено на живом
  сервере: чтение PEM (.crt + .key), TLS-слой Node с клиентским сертификатом
  и обработка отказа — совет различает «нет сертификата» и «сертификат
  отклонён» (`qrsCertAdvice`). **Не проверено:** чтение данных с настоящим
  клиентским сертификатом. Нужен экспорт из QMC (QMC → Certificates):
  `.pfx` с паролем (пароль — в `QLIK_QRS_CERT_PASSWORD`) или PEM
  `.crt` + `.key`.
