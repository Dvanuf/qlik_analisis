# Работа с сервером QlikView

Документ — о том, как анализировать приложения на **QlikView Server 12**.
Краткая версия для Qlik Sense — в [README](../README.md#подключение-к-средам).

Главное отличие QlikView от Qlik Sense: у QlikView **нет Engine API**.
Приложение открывается классическим **Doc API 12**, и тот отдаёт меньше данных,
чем QIX Engine API. Отсюда всё остальное: другие правила, другие команды,
другие ожидания от результата.

---

## 1. Как определяется платформа

Платформу **нельзя выбрать по способу подключения**: один и тот же сервер
Qlik Sense бывает доступен через Doc API, и тогда приложение ошибочно
считалось бы QlikView, а все правила по фронт-энду пропускались бы.

Поэтому платформа определяется **по типам объектов приложения**
(`src/rules/platforms.js`, `detectPlatform`):

| Типы объектов | Платформа |
|---|---|
| `UniKPI`, `UniBarChart`, `filterpane`, `action-button`, `piechart`, `scatterplot`, `uni_shecklist`, `text-image`, `slide`, `sn-table`, `hybridchart`, `pivotchart` | **Qlik Sense** |
| Только `chart`, `bar`, `line`, `pivot`, `button` и прочие типы QlikView | **QlikView** |

Проверка типа API тоже автоматическая: если у глобального объекта нет
метода `get('App')`, значит это Doc API и документ открывается через
`openDoc()` (`src/extract/engine.js`).

Выбрать платформу вручную можно флагом `--platform qlikview`
(или `rules.platform` в конфигурации). Значение по умолчанию — `auto`:
определить по данным сервера.

## 2. Что удаётся получить через Doc API

| Данные | Метод Doc API | Замечание |
|---|---|---|
| Скрипт загрузки | `getScript()` | Доступен полностью — это основа анализа QV |
| Метаданные приложения | `getAppLayout()`, `getAppProperties()` | Название, версия продукта, время последней перезагрузки, превью |
| Модель данных | `getTablesAndKeys()` | Таблицы, поля, ключи, число строк, NULL, кардинальность, плотность информации |
| Объекты (листы, чарты) | `getObjects()` | **Чаще всего пусто** — см. раздел 5 |
| Переменные | `getTextMacros()` | Имена и значения |
| Подключения к данным | `getConnections()` | Часто отдаёт подключения **уровня сервера**, а не приложения |
| Связи между таблицами | `getAssociationScores()` | Метод есть не во всех API; при отсутствии правило пропускается с объяснением |

Список документов сервера (`GetDocList`) работает и на QlikView, и на Qlik Sense —
поэтому пакетный анализ (`analyze-all`) работает на обеих платформах.

## 3. Какие правила применяются к QlikView

Всего правил **59**. На QlikView применяются **31**, остальные **28** помечаются
как «Не применимо для платформы QlikView» и в чек-листе видны как пропущенные
с причиной, а не молча исчезают.

**Применимы на обеих платформах (26):**

| Домен | Правила |
|---|---|
| Модель данных | P005, P012, R005–R007, R009–R012, R020, R021 |
| Скрипт загрузки | S001–S007, S009–S013, S015–S019 |
| Дашборд и объекты | R013 |
| Переменные | Q007 |
| Подключения и окружение | R019 |

**Только Qlik Sense — на QlikView пропускаются (28):**

| Домен | Правила |
|---|---|
| Модель данных | P003, P010, R001–R003 |
| Скрипт загрузки | S008, S014 |
| Дашборд и объекты | P004, P006, P009, Q006, R008, R014–R018 |
| Меры и выражения | P001, P002, P007, P008, P011, Q001–Q005 |
| Переменные | R004 |

Основание разметки — что реально отдаёт Doc API. Правила, которым нужен
фронт-энд, помечены как `qlik-sense`: на QlikView их нечего проверять,
а «неиспользуемое поле» без списка объектов доказать нельзя.

## 4. Подключение к серверу

### 4.1. Через хаб (браузерная сессия)

QlikView Server не имеет Engine API, поэтому подключение идёт через хаб
по адресу `wss://<host>/app/<appId>` с браузерной сессией.

```bash
node bin/analyze.js analyze --url 'wss://qlikview.corp.local/app/<appId>' \
  --cookie "$QLIK_COOKIE" --csrf-token "$QLIK_CSRF_TOKEN" --insecure --platform qlikview
```

Что требуется:

| Что | Где взять | Зачем |
|---|---|---|
| Cookie `X-Qlik-Session` | DevTools браузера → Application → Cookies | Сессия хаба |
| `qlik-csrf-token` | параметр рукопожатия `wss://…/app/<id>?qlik-csrf-token=…` | Без него хаб отвечает 403 |
| `X-Qlik-XrfKey` | заголовок запросов к REST API хаба | Нужен для списка приложений и метаданных |
| `--insecure` | — | Самоподписанный сертификат (обычная ситуация) |

Cookie и токен можно задать переменными окружения: `QLIK_COOKIE`,
`QLIK_CSRF_TOKEN`, `QLIK_XRF_KEY` (или именами из конфигурации —
`cookieEnv`, `csrfTokenEnv`, `xrfKeyEnv`).

В URL движка автоматически добавляются `qlik-csrf-token` и `reloadUri`
(`buildEngineUrl` в `src/extract/engine.js`).

### 4.2. Десктоп-приложение

В десктопе переключатель платформы («Определить автоматически / Qlik Sense /
QlikView 12») находится на вкладке «Подключение» — для QlikView выбирать
платформу вручную обычно не нужно: она определяется по типам объектов.

Кнопка «Войти в хаб» открывает окно авторизации, само перехватывает
cookie и CSRF-токен и заполняет форму. Если хаб недоступен для входа
через приложение (другое развёртывание, другой путь), те же значения
вводятся руками в блоке «Дополнительно — ручной ввод»: пользователь,
пароль, cookie сессии, XSRF-ключ, CSRF-токен.

### 4.3. Проверка подключения

```bash
node bin/analyze.js doctor --url 'wss://qlikview.corp.local/app/<appId>' \
  --cookie "$QLIK_COOKIE" --csrf-token "$QLIK_CSRF_TOKEN" --insecure
```

`doctor` показывает, на каком шаге соединение ломается, и расшифровывает
коды: 403 — нет сессии хаба, 4204 — приложение не найдено, 4203 — нет прав,
EPROTO — схема не совпадает с портом.

## 5. Ограничения QlikView

**Объектный анализ недоступен.** Doc API обычно не отдаёт листы и чарты
(`getObjects` возвращает пустой список), поэтому по QV-приложениям
проверяются **скрипт и модель данных**, но не выражения объектов.
Это ограничение API, а не дефект инструмента: 28 правил помечены
«Не применимо для платформы QlikView».

Дополнительно по Doc API:

- **не реализованы** проверки master items, закладок, расширений и тем —
  этих объектов в QlikView 12 нет;
- **подключения к данным** часто приходят уровня сервера, а не приложения:
  судить по ним об использовании нельзя, и правило R019 помечается
  пропущенным;
- **связи между таблицами** запрашиваются методом `getAssociationScores`,
  которого нет не во всех сборках — при отсутствии правило пропускается
  с объяснением;
- у QV-приложений, импортированных в Sense (например `01_EX_App_QV`),
  объекты приходят **без ссылок на поля** — правила «неиспользуемое
  поле/таблица» там недоказуемы и пропускаются с объяснением.

Для полного покрытия фронт-энда QV нужен QlikView Engine или COM Automation
на Windows с QlikView Desktop.

## 6. Офлайн-режим

Сервер не нужен — анализируется выгруженный скрипт.

```bash
node bin/analyze.js analyze --script "sales.qvs"   # экспорт скрипта из QlikView Desktop
```

Скриптовые правила (S001–S007, S009–S013) работают одинаково для Qlik Sense
и QlikView: синтаксис скрипта у них общий. Правила по модели данных в
офлайн-режиме ограничены тем, что восстанавливается из скрипта.

### 6.1. Выгрузка скрипта из `.qvw`

Формат `.qvw` — проприетарный бинарный контейнер, офлайн он не разбирается:
`--qvw` вернёт пустой анализ с пояснением. Скрипт нужно выгрузить заранее.

**Способ 1 — макрос (Windows, QlikView Desktop с лицензией на автоматизацию):**

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\qv-export-script.ps1 `
  -Path "\\qv01\Apps\Sales.qvw"
```

Макрос пробует несколько способов получить текст скрипта и использует
первый сработавший; если не подошёл ни один — выводит инструкцию по
ручному экспорту. **Код написан по открытым источникам и не проверялся на
вашем стенде** — прогоните на копии документа и сверьте результат с оригиналом.

**Способ 2 — вручную (надёжный путь):**

1. Открыть документ в QlikView Desktop.
2. Редактор скрипта: Edit Script (Ctrl+E).
3. File → Export → Script… → сохранить как `.qvs`.
4. `node bin/analyze.js analyze --script "<файл>.qvs"`

В десктоп-приложении файл открывается через «Анализ файла…» —
фильтр `Qlik-файлы` (`qvs`, `qvw`, `txt`).
