# План развития qlik-analyzer — 5 этапов

План утверждён пользователем 23.10.2026. **Этапы 0–4 выполнены (0.1.20 → 0.5.0), этап 5 —
только после отдельного утверждения.**

Разбор расширения QS Metadata Explorer 1.4.0 (что из него стоит перенести,
что отпадает и что уже есть у нас) — в [`QSME-ANALYSIS.md`](QSME-ANALYSIS.md).

Текущее состояние проекта — в [`STATE.md`](STATE.md). Правила работы — в [`AGENTS.md`](../AGENTS.md).

## Этап 0. Баги и корректность (patch → 0.1.20)

- [x] **Двойной вывод в логе подключения.** Блок «Скрипт загрузки / Объекты приложения /
  Модель данных / Пропущенные возможности» выводится дважды. Найти причину (двойной
  вызов или лог не очищается между запусками) и исправить.
- [x] **Обрезание скрипта.** На тестовом приложении скрипт получается длиной 3997 символов,
  а правило S010 сообщает «Незакрытая строковая константа (строка 207)». Проверить, не
  обрезается ли скрипт при чтении (лимит чанка, размер ответа, таймаут). Если скрипт
  получен не полностью — исправить чтение. Если полноту гарантировать нельзя, S010 должен
  показывать пометку «возможно, скрипт получен не полностью» и понижать важность.
- [x] **Нулевые значения в doctor.** «Объекты приложения: 0» и «0 МБ» сейчас показываются
  зелёным как успех. Нулевые и подозрительные значения показывать жёлтым с пояснением
  («пусто или API не вернул данные»).
- [x] **R007: AutoNumber.** Предложенная правка генерируется как
  `AutoNumber(ID, Key_QvdTableHeader)`. Второй аргумент должен быть строковым литералом:
  `AutoNumber(ID, 'Key_QvdTableHeader')`. Исправить генерацию и добавить тест.
- [x] **Дедупликация находок.** Одинаковые «правило + объект + текст» объединять в одну
  запись со счётчиком и списком таблиц, где они встречаются.
- [x] **Тесты этапа 0:** юнит-тесты на S010, R007, дедупликацию; проверка на примере
  приложения «01_EX_checker».
- [x] **Логи без секретов:** cookie, CSRF-токены и ключи не должны попадать в логи.
- [x] CHANGELOG + версия 0.1.20 (patch) + сборка и релиз.

## Этап 1. Вкладка «Подключение» (minor → 0.2.0)

- [x] **Пошаговый сценарий:** ① Войти в хаб → ② Загрузить список приложений →
  ③ Выбрать приложение → ④ Анализировать. Текущий шаг подсвечен, выполненные отмечены
  галочкой, недоступные неактивны. «Анализ файла…» и «Анализировать все» — в отдельную
  группу вторичных действий. Главная кнопка одна.
- [x] **Блок «Как подключиться»** сворачивать автоматически после успешного входа и
  запоминать состояние.
- [x] **Combobox вместо `<select>`** из 223 приложений: поиск по названию, фильтры по
  потоку и владельцу, мультивыбор для пакетного запуска.
- [x] **Чекбокс «самоподписанный сертификат»** — рядом с полем URL. Ссылку
  «привести в формат» оформить маленькой кнопкой.
- [x] **Переключатель платформы** подписать в углу («Платформа: Qlik Sense / QlikView 12»),
  активное состояние должно быть явным.
- [x] **Проверки подключения** — компактный чек-лист с иконками статусов
  (ок / предупреждение / ошибка), без дублей.
- [x] Тесты + CHANGELOG + версия 0.2.0 + релиз.

## Этап 2. Вкладка «Анализ» (minor → 0.3.0)

- [x] **Карточки метрик:** крупное число, подпись мельче. Две группы — «Важность»
  (error, warning, info) и «Категории» (Quality, Resources, Practices, Script). Цвет по
  важности, нули приглушены. Клик по карточке включает фильтр. Добавить итоговый скор
  приложения 0–100 с формулой, описанной в тултипе.
- [x] **Фильтры:** чипы важности и категорий со счётчиками, чип «Все» для важности,
  поиск, сортировка по колонкам. Единый язык: бейджи «Ошибка / Предупреждение / Замечание»,
  а не «error / info».
- [x] **Колонки таблицы:** добавить «Таблица» и «Строка». Клик по находке открывает панель
  просмотра скрипта с нумерацией строк и подсветкой нужного места (подсветку синтаксиса
  Qlik добавить, если это просто).
- [x] **Блок «Предлагаемые правки»:** diff «было / стало» по каждой правке, кнопки
  «Копировать» и «Применить к копии скрипта» (с экспортом изменённого скрипта в .qvs).
  Исходное приложение не модифицировать.
- [x] **Подавление находок:** комментарий `// qa-ignore <ПРАВИЛО>` на строке или перед
  блоком + глобальный список исключений (правило + приложение/таблица) с хранением в
  настройках. Подавленные находки скрывать по умолчанию с переключателем
  «показать подавленные».
- [x] **Длинные тексты находок** сворачивать, раскрытие по клику на строку.
- [x] Тесты + CHANGELOG + версия 0.3.0 + релиз.

## Этап 3. Вкладка «Правила» (minor → 0.4.0)

- [x] **Редактор правил:** включить/выключить правило, изменить важность, задать пороги
  (например, для R012 и R009). Настройки сохраняются в файле конфигурации,
  экспортируются и импортируются.
- [x] **Снижение шума:** R013 («нет превью») по умолчанию понизить до самого низкого уровня
  и дать возможность отключить. S002 не должно срабатывать на служебные таблицы вроде
  `Fields` — сделать настраиваемый список исключений.
- [x] Тесты + CHANGELOG + версия 0.4.0 + релиз.

## Этап 4. Сводный отчёт и история (minor → 0.5.0)

- [x] **Тепловая карта** «приложения × категории» и топ-10 самых частых правил.
- [x] **Колонки:** скор, количество error/warning/info, владелец, поток, дата изменения.
  Фильтры по ним.
- [x] **Прогресс-бар и кнопка «Отмена»** для «Анализировать все», с понятной ошибкой по
  отдельным приложениям (один сбой не должен останавливать весь прогон).
- [x] **История в локальную SQLite:** приложение, дата, версия правил, находки. Сравнение
  с предыдущим запуском («новые / исправлено / без изменений») и режим «только новые
  находки» относительно выбранной базовой линии.
- [x] **Экспорт:** HTML+JSON (как сейчас), плюс CSV и Excel. Для CSV и Excel — плоская
  таблица, удобная для загрузки в Qlik Sense как источник QA-дашборда: одна строка на
  находку, колонки: дата запуска, приложение, поток, владелец, правило, категория,
  важность, объект, таблица, строка, текст.
- [x] Тесты + CHANGELOG + версия 0.5.0 + релиз.

## Этап 5. Расширения — только после утверждения этапов 0–4

- [ ] **ИИ-ревью:** кнопка «Объяснить и предложить исправление» у находки и «Ревью всего
  скрипта». Провайдер модели настраиваемый (URL, ключ, имя модели), ключ хранить
  зашифрованно. В запрос передавать только нужный фрагмент скрипта с контекстом, а не всё
  приложение. Ответ показывать как подсказку, никогда не применять автоматически.
- [ ] **Сверка с GitLab:** сравнение скрипта приложения с файлом .qvs в репозитории
  (настройки: URL, токен, путь/ветка), показ diff и пометка «рассинхрон».
- [ ] **Режим CLI (headless):** `qlik-analyzer --app <id> --config rules.json --fail-on error
  --report out.json`. Код возврата по порогу важности, вывод в JSON и JUnit XML для CI.

## Требования к качеству (для всех этапов)

- Интерфейс только на русском, единый стиль терминов.
- Темы: светлая и тёмная (уважать системную).
- Доступность: фокус с клавиатуры, контраст не ниже WCAG AA, цвет не единственный носитель
  смысла (рядом иконка или текст).
- Тесты: юнит-тесты на правила (S010, R007, дедупликацию, подавление), генерацию правок и
  расчёт скора. Проверка на примере приложения «01_EX_checker».
- Логи не должны содержать cookie, CSRF-токены и ключи.
- В конце каждого этапа: обновить CHANGELOG и повысить версию (patch для этапа 0,
  minor для остальных).
