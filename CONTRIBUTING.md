# Как contributes в qlik-analyzer

## Окружение

```bash
node -v          # требуется Node.js 20+
npm install
npm test         # тесты ядра
```

Для десктоп-приложения:

```bash
cd desktop
npm install
npm run typecheck   # tsc --noEmit
npm run smoke       # автопроверка: приложение запускается и отвечает по IPC
```

## Правила разработки

1. **Ядро не знает про GUI.** Всё, что можно посчитать без Electron, живёт в `src/` и
   используется и CLI, и десктопом. UI только показывает результат.
2. **Правило = чистая функция.** Одна функция в `src/rules/*.js` с полями
   `id / category / severity / title / description / recommendation / run(ctx)`.
   Она автоматически попадёт в реестр, каталог правил, отчёт и справку.
3. **Никаких секретов в коде и конфиге.** Только имена переменных окружения
   (`passwordEnv`), значения — в `.env` (в `.gitignore`) или в секретах CI.
4. **Правило должно уметь объяснить, почему оно молчит.** Если проверка невозможна
   (например, список объектов недоступен) — вернуть пропуск с причиной, а не «ошибку».
5. **Тест на каждое правило.** Ложные срабатывания — главный источник жалоб:
   перед добавлением правила проверьте, что оно не срабатывает на корректных данных.
6. **Никаких внутренних хостов, имён и учётных данных** в исходниках, конфиге и документации.

## Как добавить правило

1. Создайте функцию в нужном файле `src/rules/` (`quality.js`, `resources.js`,
   `practices.js`, `script.js`) или в новом модуле и подключите его в `src/rules/index.js`.
2. Укажите `category` из `CATEGORIES` и `severity` из `SEVERITIES`
   (`error` / `warning` / `info`).
3. Если у правила есть аналог в QSDA Pro — добавьте соответствие в `src/rules/qsda-map.js`.
4. Добавьте тест в `test/rules.test.js`.
5. Обновите `docs/rules-vs-qsda.md` (генерируется `scripts/gen-rules-vs-qsda.mjs`).

## Как выпустить версию

**Предыдущие версии никогда не удаляются.**

```bash
cd desktop && npm pkg set version=0.1.11
npm run build
npx electron-builder --win --x64 --config.win.target=nsis
npx electron-builder --mac dmg zip
cd ..
# обновить CHANGELOG.md и desktop/release/README.md
git add -A && git commit -m "release: v0.1.11" && git tag v0.1.11
git push origin main --tags
```

Артефакты остаются в `desktop/release/`; на рабочий стол копируется только последняя версия.

## Стиль кода

- ES-модули, 2 пробела, точка с запятой;
- строки — одинарные кавычки, шаблонные литералы — для интерполяции;
- комментарии и тексты интерфейса — по-русски, код и идентификаторы — по-английски;
- без `console.log` в библиотечном коде (только в CLI и скриптах).
