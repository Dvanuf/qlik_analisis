# qlik-analyzer

**Анализ качества приложений Qlik Sense и QlikView** — десктопное приложение (Electron) и CLI
с детерминированным ядром: экстрактор данных, **54 правила** в четырёх категориях, HTML-отчёты
и режим CI. Инструмент анализа качества приложений Qlik с открытым кодом.

```
54 правила · 4 категории · CLI + десктоп (Windows/macOS) · пакетный анализ всех приложений сервера
```

## Возможности

| Блок | Что делает |
|---|---|
| **Экстрактор Qlik Sense** | Enigma.js / QIX Engine API: скрипт загрузки, объекты и выражения, модель данных (таблицы, поля, ключи, cardinality, NULL), переменные, закладки |
| **Экстрактор QlikView** | QlikView Doc API 12: скрипт, метаданные приложения, модель данных (`getTablesAndKeys`, `getAssociationScores`), список всех документов сервера |
| **Экстрактор офлайн** | Скрипт загрузки (`.qvs`/`.txt` — экспорт из Qlik Sense или QlikView), контейнер приложения Qlik Sense (`.qvs`/zip — ищем скрипт внутри) |
| **Парсер скрипта** | Свой: операторы `LOAD / RESIDENT / JOIN / CONCATENATE / INTO / LET / SET / DROP / RENAME / STORE`, метки, комментарии, строковые константы, пути вида `[lib://…]` |
| **Нормализация выражений** | Токенайзер Qlik-выражений, извлечение ссылок, канонизация для поиска дублей |
| **54 правила** | Quality (7), Resources (19), Practices (14), Script (14) |
| **Отчёты** | HTML (самодостаточный, с фильтрами), сводный HTML по пакетному прогону и JSON (CI, Jira, дашборды) |
| **Ошибки скрипта** | Движок проверяет скрипт сам — в отчёте видно **номер строки и колонку** каждой ошибки (правило S014) |
| **Модель данных в Excel** | Книга с листами «Таблицы», «Поля», «Объекты», «Измерения», «Меры», «Переменные», «Закладки», «Истории», «Master-объекты», «Подключения» |
| **Поиск по выражению** | Находим, где в объектах и в скрипте встречается произвольная формула |
| **Предлагаемые правки** | Сводные операторы (`DROP FIELD a, b, c;`) с понятным местом вставки, блок сворачивается |
| **Выгрузка для Qlik** | CSV и Excel: плоская таблица «одна строка — одна находка» (дата, приложение, поток, владелец, правило, категория, важность, объект, таблица, строка, текст) |
| **Скор приложения** | Итоговая оценка 0–100 с формулой в подсказке: 100 − (10×ошибки + 4×предупреждения + 1×замечания) × 10 ÷ число выполненных проверок |
| **Редактор правил** | Включение/выключение правила, важность, пороги (R009, R012), списки исключений; настройки в `rules.json`, экспорт и импорт |
| **Подавление находок** | Комментарий `// qa-ignore <ПРАВИЛО>` в скрипте и глобальный список исключений (правило + таблица) |
| **История прогонов** | Локальная база SQLite: приложение, дата, версия правил, скор, находки; сравнение с базовой линией (новые / исправлено / без изменений) |
| **Конфигурация** | `qlik-analyzer.config.json`: окружения, приложения, пути, правила; секреты — только через переменные окружения |
| **Диагностика** | Команда `doctor`: TCP → WebSocket → OpenDoc → листинг возможностей, с расшифровкой кодов ошибок |
| **Пакетный анализ** | Обход всех документов сервера одной сессией с кэшем, прогрессом, отменой и сводным отчётом |
| **CI** | Код возврата `--fail-on error|warning`, артефакты, готовый workflow для GitHub Actions |


## Быстрый старт

```bash
# Node.js 20+
npm install

# 1. Оффлайн: скрипт загрузки — сервер не нужен
node bin/analyze.js analyze --script "path/to/sales.qvs" --out out/report.html

# 2. Qlik Sense Enterprise on Windows
node bin/analyze.js doctor  --env qs-prod --app sales
node bin/analyze.js analyze --env qs-prod --app sales --out out/report.html

# 3. Разово, без конфигурации
node bin/analyze.js analyze \
  --host qlik-sense.corp.local --port 4747 --app-id 8f1c-… \
  --user "CORP\qlik_ro" --password-env QLIK_QS_PASSWORD --insecure

# 4. Что настроено в конфигурации
node bin/analyze.js envs

# 5. Тесты
npm test
```

> **Важно про `--password-env`:** пароль никогда не передаётся аргументом командной строки
> (его видно в истории команд и в `ps`). Укажите **имя переменной окружения**, значение
> которой лежит в `.env` (в `.gitignore`) или в секретах CI.

## Подключение к средам

### Qlik Sense Enterprise on Windows

URL движка: `ws://<host>:4747/app/<appId>` (http-порт) либо
`wss://<host>:4746/app/<appId>` (https-порт). Правило схемы зашито в код:
порт **4746 → `wss://`**, порт **4747 → `ws://`** (переопределяется полем `scheme` в конфиге).

```bash
node bin/analyze.js doctor --url ws://qlik-sense.corp.local:4747/app/8f1c-… \
  --user "CORP\qlik_ro" --password-env QLIK_QS_PASSWORD --insecure
```

- авторизация: доменный пользователь (Basic) и/или заголовок `X-Qlik-User` (имперсонация);
- `--insecure` — для самоподписанных сертификатов (на QSS это обычная ситуация);
- `doctor` подсказывает причину по кодам: 4202 (URL), 4203 (права), 4204 (нет appId),
  4205/4240 (нет движков), 401/403 (авторизация), 301/302 (указан не адрес движка).

### QlikView Server 12

QlikView Server не имеет Engine API — доступен классический **QlikView Doc API**.
Подключение идёт через хаб (`wss://<host>/app/<appId>`) с браузерной сессией.

```bash
node bin/analyze.js analyze --url 'wss://qlikview.corp.local/app/<appId>' \
  --cookie "$QLIK_COOKIE" --csrf-token "$QLIK_CSRF" --insecure --platform qlikview
```

Через хаб с forms-auth: cookie сессии `X-Qlik-Session` + query-параметр `qlik-csrf-token`
(рукопожатие движка) + заголовок `X-Qlik-XrfKey` (для REST-API хаба). В десктоп-приложении
это автоматизировано — см. «Десктопное приложение».

### Офлайн

```bash
node bin/analyze.js analyze --script "sales.qvs"   # экспортированный скрипт
node bin/analyze.js analyze --qvs    "sales.qvs"   # контейнер приложения Qlik Sense (zip)
```

Для QlikView: выгрузка скрипта из `.qvw` через COM — `tools/qv-export-script.ps1`.

Живая проверка на своём сервере: `tools/live-check.mjs` — читает сессию хаба,
подключается к движку и прогоняет настоящий анализ с отчётом по полноте
метаданных, структуре скрипта и находкам.

Для QlikView офлайн: выгрузите скрипт из QlikView Desktop
(Edit Script → File → Export → Script → `app.qvs`) и проанализируйте его как обычный скрипт.
Скриптовые правила (S001–S013, S021) работают одинаково для Qlik Sense и QlikView: синтаксис скрипта
у них общий.

### Qlik Cloud (если появится)

```bash
node bin/analyze.js analyze --url wss://<tenant>.<region>.qlikcloud.com/app/<APP_ID> --api-key "$QLIK_API_KEY"
```

## Десктопное приложение

```bash
cd desktop
npm install
npm run build     # сборка main + renderer
npm start         # запуск в dev-режиме
npm run smoke     # автопроверка: приложение само себя проверяет
```

Пять вкладок:

**Подключение** — выбор платформы кнопками (**Определить автоматически** /
**Qlik Sense** / **QlikView 12**), блок
«Как подключиться» с пошаговой инструкцией, поле URL движка с кнопкой «восстановить»,
чекбокс самоподписанного сертификата и кнопки «Войти в хаб», «Проверить подключение»,
«Загрузить список приложений», «Анализ файла…», «Анализировать все».
Ручной ввод (пользователь/пароль/cookie/XSRF/CSRF) свёрнут в блок **«Дополнительно»** —
он нужен для Qlik Cloud и Qlik Sense с прямой Basic/NTLM-авторизацией.

**Анализ** — сверху сводка (всего находок, по категориям, по уровням), кнопка
«Экспорт отчёта» (HTML+JSON в «Документы/QlikAnalyzer»), блок «Предлагаемые правки
скрипта» и раздел **«Структура скрипта загрузки»** (разделы скрипта, шаги построения
таблиц, поток по resident-источникам, недостижимый код после `EXIT SCRIPT`);
**снизу — таблица находок** с фильтрами **уровень × категория**, поиском по тексту
и счётчиком «показано X из Y». После пакетного прогона — таблица по всем приложениям.

**Правила** — каталог правил с поиском, фильтром по категории, колонками
«Описание», «Рекомендация», «Платформы» и числом срабатываний.

**Каталог функций** — библиотека готовых подпрограмм скрипта: документация,
сигнатура, код, копирование кода и вызова `CALL`, выгрузка выбранных подпрограмм
в файл `.qvs` для подключения через `lib://` и разбор собственной библиотеки.

### Вход в хаб без копирования cookie вручную

Кнопка **«Войти в хаб (откроется окно авторизации)»**:

1. приложение открывает окно браузера со страницей приложения в хабе;
2. вы вводите доменный логин и пароль в этом окне — как в обычном браузере;
3. приложение перехватывает (через CDP) рукопожатие движка, который страница открывает сама,
   и забирает оттуда `qlik-csrf-token`, а cookie сессии — из профиля Electron;
4. поля формы заполняются автоматически, данные сохраняются **зашифрованными**
   (`safeStorage`: DPAPI на Windows, Keychain на macOS) и восстанавливаются при следующем запуске.

> Доменный логин/пароль, введённые прямо в форме приложения, **не работают** для хабов
> с forms-auth: прокси не предлагает схему Basic/Negotiate и отвечает 403.
> Нужна браузерная сессия.

## Пакетный анализ

Одна сессия движка обходит **все документы сервера** и прогоняет по каждому те же правила.

```bash
node bin/analyze.js analyze-all \
  --url 'wss://<host>/app/<любой appId>' \
  --cookie "$QLIK_COOKIE" --csrf-token "$QLIK_CSRF" --insecure \
  --platform qlikview \
  --out-dir reports/batch --summary reports/batch/summary.json
```

Флаги: `--limit N` (первые N), `--app-ids id1,id2` (выборочно), `--pause 1000` (пауза между
приложениями в мс), `--cache-dir <dir>`, `--no-cache`.

Что происходит:
- одна сессия на весь прогон, приложения открываются по очереди;
- **кэш** по `appId` + времени последней перезагрузки — повторный прогон не открывает
  неперезагруженные документы заново (ускорение ×5–10);
- **мягкий режим**: ошибка на одном приложении не останавливает прогон, а попадает в отчёт;
- сводный отчёт `summary.html` — таблица всех приложений, топ-20 проблемных, суммарная
  экономия памяти; плюс `summary.json` и отдельный JSON по каждому приложению.

В приложении — кнопка **«Анализировать все»** с прогрессом и **«Прервать»**.

## Какие данные собираются по приложению

Инструмент читает **метаданные и структуру** приложения — данные строк он не запрашивает.

**Список приложений сервера** (метод `GetDocList`): идентификатор, название, размер файла,
дата изменения, число подключённых пользователей, дата создания, признак публикации,
привилегии пользователя, описание.

**По каждому приложению:**

| Блок | Что читается | Источник |
|---|---|---|
| Скрипт загрузки | полный текст скрипта | `getScript` |
| Модель данных | таблицы: имя, число строк, ключевые поля, синтетический ключ, direct discovery | `getTablesAndKeys` |
| | поля: имя, таблица, теги, ключ/не ключ, число строк, число не-NULL, число уникальных значений, наличие NULL, плотность информации, subset ratio | `getTablesAndKeys` |
| Объекты | имя, тип, описание, выражения измерений и мер | `getObjects` + `getLayout` (только Qlik Sense) |
| Переменные | имя, значение (определение), описание | `getVariable` / `getTextMacros` |
| Связи таблиц | кардинальность связи (для правила R011) | `getAssociationScores` |
| Свойства приложения | название, идентификатор, превью, дата перезагрузки, версия продукта | `getAppLayout` / `getAppProperties` |
| Закладки | идентификатор, название, состав объектов | `getBookmarks` (только Qlik Sense) |
| Расширения | идентификатор, имя | `getObjects` (только Qlik Sense) |

**Что не собирается:** значения строк данных, содержимое таблиц приложения, персональные
данные пользователей. Всё, что прочитано, остаётся на вашем компьютере — наружу
(в Qlik, на сторонние сервисы) ничего не отправляется.

## Что проверяют правила

Каждое правило имеет описание (что именно проверяется) и рекомендацию
(что с этим делать) — обе формулировки видны в каталоге правил, в отчёте
и в интерфейсе приложения.

Полный список правил с пояснениями — в таблицах раздела «Правила» выше
и в самом приложении (вкладка «Правила», где есть поиск и фильтр по категории).

### Применимость правил по платформам

У каждого правила указано, на какой платформе оно применимо
(`src/rules/platforms.js`):

| Платформа | Что попадает в разметку |
|---|---|
| **Qlik Sense** | Правила, которым нужен фронт-енд: объекты, листы, выражения чартов |
| **QlikView 12** | Правила, опирающиеся только на скрипт и модель данных |
| **Обе платформы** | Скриптовые правила (S001–S013, S021) и правила по модели данных |

Платформа **определяется по типам объектов приложения**: QlikView 12 знает
набор типов `chart`, `bar`, `pivot`, `button`, а в Qlik Sense 12 появились
`UniKPI`, `filterpane`, `action-button`, `piechart` и другие. По способу
подключения судить нельзя: один и тот же Sense-сервер бывает доступен
через Doc API.

Флаг `--platform` и настройка `rules.platform` переопределяют определение
(`--platform auto` — определить по данным сервера, значение по умолчанию).

Правило, неприменимое к текущей платформе, не запускается, а помечается
в отчёте и в каталоге правил: «Не применимо для платформы QlikView».

Правила, утверждающие, что поле или таблица **не используются** во фронт-энде,
дополнительно требуют данных об использовании: если сервер отдал объекты, но
не отдал сведений о применяемых ими полях, проверка пропускается с
объяснением — иначе рождались бы сотни ложных находок.

Не реализованы проверки, требующие master items, закладок, расширений и тем:
эти объекты доступны только в Qlik Sense, а в QlikView 12 их нет.

## Сервер для нескольких сотрудников

Веб-сервер: сотрудники открывают отчёты в браузере, анализ выполняет сервер.
**Ядро то же самое** — те же 54 правила и те же HTML-отчёты.

```bash
npm install
node server/server.js                    # http://127.0.0.1:8080
node server/server.js --host 0.0.0.0      # доступ из сети
```

Что умеет:
- список приложений сервера Qlik, запуск анализа одного или всех;
- **очередь фоновых задач** — прогресс в реальном времени (SSE), отмена;
  параллелизм по умолчанию 1, чтобы не выжигать лицензии движка;
- история отчётов на диске, каждый — самодостаточный HTML + JSON;
- **разграничение прав**: роль `analyst` запускает анализ, `viewer` только читает;
- **три режима аутентификации**: `none` (локально), `basic` (HTTP Basic),
  `proxy` (доменный вход через IIS/nginx с Kerberos — рекомендуется).

REST API: `/api/apps`, `/api/analyze`, `/api/analyze-all`, `/api/jobs`,
`/api/reports`, `/api/stream`, `/api/health`.

Подробности, конфигурация и развёртывание — [`server/README.md`](server/README.md).

## Команды CLI

| Команда | Назначение |
|---|---|
| `analyze` | Анализ одного приложения или файла |
| `analyze-all` | Пакетный анализ всех приложений сервера + сводный отчёт |
| `doctor` | Диагностика подключения с расшифровкой кодов ошибок |
| `envs` | Что настроено в конфигурации |

Ключевые флаги `analyze`: `--url` / `--env` + `--app`, `--script` / `--qvs`, `--out`,
`--json`, `--graph`, `--platform qlik-sense|qlikview`, `--cookie`, `--xrf-key`, `--csrf-token`,
`--user`, `--password-env`, `--insecure`, `--fail-on error|warning`, `--quiet`.

## Конфигурация

`qlik-analyzer.config.json` в корне проекта (путь переопределяется `--config` или
переменной `QLIK_ANALYZER_CONFIG`). Приоритет: **CLI-флаг > переменная окружения > конфиг > умолчание**.

```json
{
  "environments": {
    "qs-prod": {
      "type": "qlik-sense",
      "host": "qlik-sense.corp.local",
      "port": 4747,
      "user": "CORP\\qlik_ro",
      "passwordEnv": "QLIK_QS_PASSWORD",
      "qlikUser": "CORP\\qlik_ro",
      "insecure": true
    },
    "qv-prod": { "type": "qlikview", "doc": "\\\\qv01\\Apps\\Sales.qvw" }
  },
  "apps": { "sales": { "env": "qs-prod", "appId": "8f1c-…" } },
  "paths": { "out": "reports/{env}/{app}/report.html" },
  "rules": { "disabled": ["P010"], "maxExpressionLength": 200 }
}
```

**Секреты в конфиге не хранятся** — указывается имя переменной (`passwordEnv`), значение берётся
из окружения или из `.env` (шаблон — `.env.example`, сам `.env` в `.gitignore`).

Принцип: **детерминированное ядро + ИИ-надстройка**. Ядро даёт воспроизводимые факты
(что сломано, что не используется, где тормозит) — их и проверяет CI. ИИ подключается
поверх: объяснение находок, генерация фиксов, семантическое сравнение формул,
автогенерация тестов на enigma-mock, регрессионное сравнение «было / стало».

## Ограничения

- **QlikView Server 12: объектный анализ недоступен.** Doc API не отдаёт листы и чарты
  (`getObjects` возвращает пустой список), поэтому по QV-приложениям проверяются **скрипт и
  модель данных** (Script + Resources), но не выражения объектов. Такие правила помечены
  как «только Qlik Sense» и при анализе QV-приложения пропускаются с пометкой
  «Не применимо для платформы QlikView». Для полного покрытия QV нужен QlikView Engine
  или COM Automation на Windows с QlikView Desktop.
- Точный расход памяти статически недоступен: его даёт только отчёт
  о памяти движка. Здесь оценивается объём в строках.
- Модель данных, восстановленная из скрипта (fallback), — эвристика: ключи и cardinality
  из неё не восстановить.
- Правила «неиспользуемое поле/таблица» в файловом режиме **пропускаются с пометкой**:
  без списка объектов доказать неиспользуемость нельзя.
- Семантически равные, но структурно разные формулы не ловятся — это задача ИИ-слоя.
- Приложение не подписано — SmartScreen/Gatekeeper предупредят при первом запуске.

## Разработка и выпуск версий

```bash
npm test                       # тесты ядра (node:test)
cd desktop && npm run typecheck # tsc --noEmit
cd desktop && npm run smoke     # автопроверка приложения
```

**Правило выпуска: предыдущие версии никогда не удаляются.**

1. Артефакты всех сборок лежат в `desktop/release/` и не удаляются.
2. Правка `version` в `desktop/package.json`, коммит, тег `v<версия>`.
3. `CHANGELOG.md` — что изменилось в каждой версии; `desktop/release/README.md` — реестр сборок.
4. На рабочий стол копируется **последняя** версия; остальные хранятся в проекте.

```bash
cd desktop && npm pkg set version=0.1.11
npm run build
npx electron-builder --win --x64 --config.win.target=nsis
npx electron-builder --mac dmg zip
cd .. && git add -A && git commit -m "release: v0.1.11" && git tag v0.1.11
git push origin main --tags
```

Восстановить конкретную версию: `git checkout v0.1.10 && cd desktop && npm ci && npm run build`.

### Как добавить правило

- правило = одна функция в `src/rules/*.js` с полями
  `id/category/severity/title/description/recommendation/run(ctx)`;
  она автоматически попадёт в реестр, каталог правил и отчёт;
- функция Qlik — в `src/rules/qfuncs.js`;
- каталог правил — `src/rules/index.js` (`CATEGORIES`, `ALL_RULES`);
- применимость по платформам — `src/rules/platforms.js`.
